DeepSeek-on-OpenRouter requests no longer hard-pin the upstream provider. The layer previously sent `{"only": ["DeepSeek"], "allow_fallbacks": False}`, so when the DeepSeek *upstream account* ran out of balance (HTTP 402 `Provider returned error`, `provider_name: DeepSeek`, `is_byok: False`) every `deepseek/*` request failed even though ~17 other providers served the same model and OpenRouter had already marked DeepSeek `status: -5`. Routing now uses `order` + `allow_fallbacks: True`, keeping DeepSeek first for prompt-cache warmth while letting OpenRouter route past it during an outage.

Fallback cost is bounded by a new `max_price` ceiling, configurable per tier via `provider_kwargs` (`max_price_prompt` / `max_price_completion`) and defaulting to $0.70/$1.40 per 1M tokens on the capable tier and $0.15/$0.30 on the cheap tier — measured so several healthy providers stay eligible while excluding the ~$1.740/$3.480 tail. `allow_fallbacks=False` remains available as an explicit opt-in.

Relatedly, an upstream provider's 402 is now treated as transient and retried, so a retry can re-route to a healthy provider. A 402 for our *own* exhausted OpenRouter credits (which carries no `provider_name`/`is_byok: False` markers) still fails fast, as does a BYOK provider's 402.
